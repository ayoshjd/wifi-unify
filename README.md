# 把 4 台家用路由器，改成一个 Wi-Fi

> **一句话**：把"每台路由器各自 NAT、各自发 SSID"的家用网络，改成"单一 SSID + 唯一 DHCP + 单一网段 + 信道错开"，让手机在房间之间自己换 AP，不用再手动切 Wi-Fi。
>
> 下文把这次改造的对象称为**参考部署**：4 台消费级设备（光猫一体机 ×1、双频路由器 ×1、单频 2.4G 路由器 ×1、FTTR 从设备 ×1），既有网线，**零新增硬件**。文中数值均为某一实际部署的实测值，仅供参考，不构成对其他环境的保证。

---

## 1. 这跟你有没有关系

命中 2 条以上，这套打法大概率适用：

- 家里有 2 台以上路由器（或光猫 + 路由 + 旧路由堆着用），每个房间一个 Wi-Fi 名；
- 走到另一个房间要**手动选网络**，或者"信号满格但上不了网"；
- 打印机、投屏、智能设备跨房间连不上，或者时好时坏；
- 想加 Mesh 但不想换设备、不想花钱。

如果你要的是"企业级无缝漫游"或"厂商 Mesh 专有协议"，直接看第 4 节，这套不合适。

---

## 2. 为什么值得做（三个理由）

### 2.1 Mesh 的零成本平替

如果你正在考虑"买一套 Mesh"，先看这一条：**不换设备、不加硬件**，把手里几台路由器组合成"看起来像一个网络"的样子——网络名不变、密码不变、地址段不变，手机从房间走到房间不用你手动切。

但**这不是 Mesh，代价必须先摆在前面**：

| 代价 | 具体表现 |
|---|---|
| **换 AP 由客户端自己决定，不是网络指挥** | 没有 802.11r/k/v 这类快速漫游协议，网络无法"通知"或"引导"手机换到更合适的 AP；手机粘着远处那台不走，网络只能干看着 |
| **没有统一管理面** | 几台设备各自一套页面：改一个参数要登 N 次、点 N 套按钮；没有"一键下发"，也没有统一固件 |
| **断流时间取决于客户端** | 参考部署实测能到 1 秒内，但那是**特定手机 + 特定固件**的结果，不代表每台设备都如此；老设备可能 2–3 秒，甚至重连失败 |
| **没有集中优化** | 负载均衡、频段引导、弱信号剔除，要么没有，要么各家用各家的不可见算法 |

> 结论口径：**体验接近 Mesh 的漫游，成本为零，但不是 Mesh。** 如果断流 1 秒不可接受（VoWiFi 通话、竞技游戏、长时间上传），请买真正的 Mesh 或企业级 AP，不要用这套方案硬扛。

### 2.2 老旧路由再利用，而不是扔掉

多数家庭抽屉里都躺着一两台淘汰的路由器。它们通常还能用，只是被"各自 NAT + 各自 SSID"的用法浪费了。改成 AP，等于**零成本换一个覆盖点**。

能用的前提有三条，缺一不可：

| 前提 | 说明 |
|---|---|
| 能**关闭 DHCP** | 否则它会和主网关抢着发地址 |
| 能做**桥接 / LAN 上联** | WAN 口空置，网线插 LAN 口；没有 AP 模式的设备，至少要做到"关 DHCP + 改 LAN 地址 + 插 LAN 口" |
| 至少**单频可用** | 只有 2.4G 也能用，但质量有折损 |

折损要明说：参考部署实测，那台只有 2.4G + 百兆上联的设备，网关 ping 均值约 **16.5 ms**、最大 **108 ms**、抖动 **16.2 ms**，而 5G 近场是均值 **2.1 ms**、抖动 **1.9 ms**——**差一个数量级**。它仍然 0 丢包、能正常上网，但时延敏感的应用会感觉到。老旧设备的正确定位是"补盲区"，不是"主力覆盖"。

### 2.3 跨品牌混用：靠约定，不靠协议

这套打法不要求所有设备同品牌、同固件，甚至不要求同一年代。它只要求几台设备**共同遵守同样的几条**：

1. 同一个二层广播域（AP/桥接模式，WAN 口空置）；
2. 只有一个 DHCP 服务器；
3. 同一个 SSID、同一个 PSK、同一档加密与认证方式。

这几条是**通用约定**，不是某家厂商的私有协议——所以跨品牌才成立。你换掉其中任何一台，只要新设备也能遵守这几条，整体照样工作。

但品牌差异会带来实实在在的麻烦：

| 差异 | 实际麻烦 |
|---|---|
| 页面菜单结构不同 | 同一个功能，A 家叫"无线设置 → 主人网络"，B 家叫"高级 → WLAN"，每次都要先摸清结构再动手 |
| 保存按钮数量不同 | 有的设备 2.4G/5G 各有一个"保存"，只点一个就只生效一半 |
| 部分字段隐藏或不可见 | 加密方式、PMF、功率可能根本不在页面上，只能"有则统一、无则记录"，不能凭空假设 |
| 个别设备没有 AP 模式 | 只能靠"关 DHCP + 改 LAN 地址 + 插 LAN 口"手工模拟，顺序错了会失联 |
| 管理会话互斥 | 有的设备同时只允许一个管理员，脚本读取和人工登录会互相踢下线 |

跨品牌混用的真正含义是：**你放弃"统一管理"的便利，换取"不换设备"的自由。**

## 3. 结果（参考部署实测，仅供参考）

> 以下数值来自一次实际部署，仅作量级参考，不同环境差异很大——请不要把它们当作目标值。

不是为了证明"性能变强"，而是证明**手动切换这件事消失了**。

| 指标 | 改造前 | 改造后 |
|---|---|---|
| 广播的 SSID 名 | 4 个不同名字（含主网关 2.4G/5G 各一个名字） | **1 个** |
| 网段 | 3 段（1 个主网段 + 2 台二级路由各自的 `192.168.<x>.x`） | **1 段** |
| DHCP / NAT | 主网关 + 2 台二级路由（双重 NAT） | **1 台 DHCP、1 层 NAT** |
| 换房间 | 手动切 SSID，切换 = 断开重连 | **自动重关联**：实测 3 次，每次 **< 1 s** |
| 网关 ping（近场，300 × 1 s） | 0% 丢包 / 均 4.60 ms / 最大 33 ms / 抖动 2.32 ms | 0% / **2.09** / **13** / **1.89** |
| 外网 ping（60 × 1 s） | 0% / 10.12 / 21 / 2.68 | 0% / **7.68** / 21 / **2.27** |
| 远端房间（2.4G，百兆上联） | — | 0% / 16.54 / 108 / 16.16（**不是故障**，见下） |
| 打印机 | 挂在二级路由后面，主网不可达 | 主机名 + 9100 端口可达 |
| 新增硬件 | — | **0** |

两点必须说清：

- **远端房间的时延明显更高**（均值 16.5 ms vs 近场 2.1 ms）。原因是那台 AP 只有 2.4G + 百兆上联，且 2.4G 只有 3 个互不重叠信道、4 个广播源必然有一对复用。这是**结构代价**，不是改造失败。
- **吞吐没有纳入验收**。参考部署中曾发现上联链路只协商到 10 Mbps（线材/端口层），在这种链路上测出来的任何吞吐数字都无效。详见 [03-验收与取证 · 5.2 吞吐的前置条件](playbook/03-验收与取证.md)。

## 4. 适用 / 不适用

| | 条件 |
|---|---|
| ✅ 适用 | AP 之间**有线可达**（已有网线，或能补一条） |
| ✅ 适用 | 设备能改：关 DHCP、改 LAN 地址、设固定信道、改 SSID/加密 |
| ✅ 适用 | 能接受"重连式漫游"：换 AP 会断 < 1 s，普通刷网页/看视频无感 |
| ✅ 适用 | 家庭/小型办公，设备在十几到几十台量级 |
| ❌ 不适用 | 要求**真正无缝**：VoWiFi 通话、竞技游戏、长时间大文件上传不能接受任何断流 |
| ❌ 不适用 | 只能用**无线中继/Mesh 专有协议**组网（没有网线可拉） |
| ❌ 不适用 | 固件锁死：不能关 DHCP、不能改 LAN 地址、信道强制"自动"且不可关 |
| ❌ 不适用 | 需要 VLAN 隔离、多 SSID 分权、802.1X 的企业环境 |
| ❌ 不适用 | 想靠刷第三方固件解决（多数运营商定制设备刷坏 = 宽带参数丢失，且无法还原） |

## 5. 核心结论（浓缩成 6 条）

1. **单一广播域**：AP 之间必须是二层直通（AP 模式/桥接，WAN 口空置），不能各自 NAT。
2. **唯一 DHCP**：只留一台发地址；其余全关，管理地址固定在池外。
3. **SSID / PSK / AKM / 加密逐项一致**：只统一"名字和密码"不够，认证方式不一致会在换 AP 时反复四次握手。
4. **信道错开**：2.4G 只有 1/6/11 三个非重叠信道，广播源多于 3 个时**必然有复用**，按"新增同频对最少"分配，不要追求零复用。
5. **一次只改一项，改完逐字段回读**：一个页面常有多个"保存"按钮（分频段），漏一个就前功尽弃。
6. **先有 before，才有"改好了"**：没有改造前的链路速率/双工/ping 质量，后面所有数据都无法归因。

## 7. 关于本文的数据与脱敏

- 所有数据均为**某一实际部署的实测值**（4 台消费级设备、普通住宅），仅供参考，不是厂商标称值，也不构成对其他环境的保证；不同固件、不同户型结论会变。
- 文中 SSID、密码、MAC/BSSID、内网 IP、设备型号、厂商信息、地理位置与房间名均已脱敏：SSID 用 `HomeWiFi`、IP 用 `192.0.2.x`、BSSID 用 `AA:BB:CC:DD:EE:FF` 这类占位。
- 这次部署收口时采用**只读 + 文档**方式：改配置、换线由人现场操作，测量与取证用脚本完成。

| 位置 | 是什么 | 定位 |

二者可以独立使用：只读手册也能完成一次改造；只用工具包也能按阶段执行并留证。手册回答「为什么、怎么判断」，工具包回答「用什么命令、证据怎么落盘」。

工具包需要 **Windows + PowerShell 7+（`pwsh`）**，不支持 Windows PowerShell 5.1。原因有二：`Test-AdminSession.ps1` 使用 `Invoke-WebRequest -SkipCertificateCheck`，且 `Test-AdminSession.ps1` / `Test-NetConfigConsistency.ps1` 使用 `Test-Connection -TargetName`，这两个参数在 5.1 中不存在；同时 12 个脚本都是 UTF-8（无 BOM），5.1 会按 ANSI 代码页解析中文，使中文匹配规则失效。WLAN 采集、事件日志与网络栈命令依赖 Windows；纯文件类脚本（变更记录、回读比对、阶段闸门、脱敏扫描）可在任意装有 `pwsh` 7 的系统上运行。脚本默认只读，或只写报告/记录/快照，不修改设备与本机网络配置。
