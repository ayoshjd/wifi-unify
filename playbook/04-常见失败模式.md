# 04 · 常见失败模式

> 来源：一次实际部署的 19 条事故台账与 13 条根因（均已泛化），抽象成与环境无关的 18 条失败模式。
> 用法：开工前通读，标出本环境最可能中的三条；每完成一组动作，对照「早期发现」自查一次。
> 每条都回答：**长什么样、为什么会发生、怎么最早发现、不做会怎样。**

## §1 失败模式总表

### F01 把推测当事实

| 项 | 内容 |
|---|---|
| 典型表现 | 「这台没广播」「这个密码不支持特殊符号」「那台离线了」——结论只有一次扫描/一次 ping 支撑 |
| 根因 | 把单源观察写成陈述句；没有证据等级；后续步骤建立在错事实上 |
| 早期发现 | 每个关键结论问三句：来源是什么？换一种方法还成立吗？有没有反例？答不上就标「待复核」 |
| 不做会怎样 | 基于错事实做的改动全部白做；例如把「未广播」当事实去开无线，实际是扫描距离不够，改完仍不通 |

### F02 页面显示成功但没持久化

| 项 | 内容 |
|---|---|
| 典型表现 | 点保存后提示成功，刷新/重进页面值变回原样；或设备重启后恢复默认 |
| 根因 | 前端只改显示未提交；保存被后台任务覆盖；配置未写入持久存储 |
| 早期发现 | 保存后 **强刷 + 退出重进 + 回读**；关键项再触发一次重启后回读（谨慎） |
| 不做会怎样 | 你以为改了，下一台按错误基准配置；最后全屋参数对不上 |

### F03 多个保存按钮只保存了一部分

| 项 | 内容 |
|---|---|
| 典型表现 | 2.4G 改了、5G 没改；或安全设置改了、SSID 没改；页面分频段/分区块各有保存 |
| 根因 | 页面按区块提交；执行者只点了视野内的一个按钮 |
| 早期发现 | 进页面前先数「保存/应用」按钮数量并记录；每改一段就保存并回读该段 |
| 不做会怎样 | 同名 SSID 下 5G 仍是旧名/旧密，客户端在 5G 反复失败；排查时会误判为设备故障 |

### F04 断链网卡残留地址/路由导致双网关

| 项 | 内容 |
|---|---|
| 典型表现 | 网线拔了，网卡仍有旧 IP/旧默认路由；插回瞬间出现两个默认网关；时通时不通 |
| 根因 | 接口断开时地址/路由不参与转发，但仍留在表里；插线瞬间同时生效 |
| 早期发现 | 插线前后各跑一次 `route print -4` 与 `ipconfig`，比对默认路由条数与同网段地址；插线后立即回读 |
| 不做会怎样 | 改动后在「看起来正常」的网络里出现随机断流；你会误判为无线问题，实际是本机路由冲突 |

### F05 测速前不测链路

| 项 | 内容 |
|---|---|
| 典型表现 | 无线测出 8–10 Mbps，被当成设备/配置问题；换设备仍一样 |
| 根因 | 上联网线/水晶头/端口协商只有 10 Mbps；或一端百兆一端千兆协商失败 |
| 早期发现 | 测速前先看两端 `LinkSpeed` 与双工；低于 100 Mbps 一律先换线/换口 |
| 不做会怎样 | 把线材问题归因于无线，反复改配置、换设备，成本翻倍且不解决 |

### F06 验收口径后置

| 项 | 内容 |
|---|---|
| 典型表现 | 做完才讨论「吞吐算不算」「断流多少算通过」「ping 不通从机算不算失败」 |
| 根因 | 没有在开工前写三分法；判据、观察项、不作判据混在一起 |
| 早期发现 | 开工前检查：验收文档里是否有「判据/观察项/不作判据」三节，且每条有阈值与证据 |
| 不做会怎样 | 结论反复、双方各执一词；复盘时无法判断是方案问题还是口径问题 |

### F07 单源验证代替交叉验证

| 项 | 内容 |
|---|---|
| 典型表现 | 只用一个 `netsh` 扫描判断 BSSID；只用页面判断信道；只用 ping 判断在线 |
| 根因 | 单源有缓存/盲区/权限限制；不同工具结果本就可能不同 |
| 早期发现 | 关键结论至少两源；BSSID 用「客户端扫描 + AP 回读 + 主网关拓扑」三路 |
| 不做会怎样 | 漏掉隐藏 BSSID、旧 SSID、离线从机；验收通过但住户仍遇到问题 |

### F08 还原只做一半

| 项 | 内容 |
|---|---|
| 典型表现 | 删了临时静态 IP，但网卡 DHCP 仍是禁用；删了临时路由，但 DNS 还是静态 |
| 根因 | 只还原「看得见的那一项」，没有回读整组状态 |
| 早期发现 | 还原后回读四态：地址获取方式、默认路由、DNS、代理；四项都回到自动/默认 |
| 不做会怎样 | 本机看似能上网，换网络后拿不到地址；下次施工一开始就踩坑 |

### F09 敏感信息整页倾倒

| 项 | 内容 |
|---|---|
| 典型表现 | 为了「留证」把无线设置整页复制进报告，密码/PSK 明文进入文档与日志 |
| 根因 | 没有字段白名单；不知道哪些字段敏感 |
| 早期发现 | 记录前先列字段白名单；密码只记「已设置/长度/是否一致」，不记明文；分享前跑泄漏扫描 |
| 不做会怎样 | 密码随文档扩散；开源/分享时无法回收；住户网络安全直接受损 |

### F10 管理会话争抢 / 登录锁定

| 项 | 内容 |
|---|---|
| 典型表现 | 页面提示「其他用户正在设置」；改完不生效；连续登录失败后锁定几十秒 |
| 根因 | 多标签/多设备同时登录；设备只允许单会话；失败重试触发防爆破 |
| 早期发现 | 施工前关闭其他管理页；失败一次即停；记录设备是否有锁定策略 |
| 不做会怎样 | 改动被另一会话覆盖，回读结果自相矛盾；锁定期间无法回滚 |

### F11 前台执行切断自身管理通路

| 项 | 内容 |
|---|---|
| 典型表现 | 在前台点「断开 Wi-Fi/重启/改管理地址」，页面立刻失联，任务中断 |
| 根因 | 操作会话与被切断的链路是同一条；没有带外通道 |
| 早期发现 | 执行前问：这一步会不会切断我当前的连接？会，就改后台脚本/先建带外 |
| 不做会怎样 | 执行者失联，现场无人能恢复；比配置错误本身更严重 |

### F12 命令/参数错误产出假结果

| 项 | 内容 |
|---|---|
| 典型表现 | 命令报「参数不存在」，但脚本继续跑，输出「100% 丢包」；或统计了 0 个样本却报通过 |
| 根因 | 没有检查退出码/样本数；参数拼写错误被当成业务结果 |
| 早期发现 | 先跑最小样本；检查命令退出码与样本数；0 样本一律判「无效」不判「通过」 |
| 不做会怎样 | 用假数据下结论；例如把「没测到」当成「全丢」，或把「没事件」当成「无断流」 |

### F13 before/after 不成对

| 项 | 内容 |
|---|---|
| 典型表现 | 只有 after 快照；before 是记忆或口头描述；diff 无法生成 |
| 根因 | 开工前没导出基线；或导出格式不一致 |
| 早期发现 | 每阶段开始前检查 before 目录是否存在、格式是否与 after 相同；阶段闸门强制成对 |
| 不做会怎样 | 无法证明改动只影响计划内项；出问题时无法判断哪一项导致 |

### F14 目标写成概括句，没展开到设备×频段

| 项 | 内容 |
|---|---|
| 典型表现 | 目标写「统一 SSID」，实际只改了 2.4G；5G 仍旧名；某台设备没纳入 |
| 根因 | 没有逐台逐频段矩阵；把「计划」当「完成」 |
| 早期发现 | 目标矩阵每行都有当前值/目标值/证据；验收逐行勾 |
| 不做会怎样 | 验收时才发现漏项，临时加变更，打乱顺序，增加断网窗口 |

### F15 自动优化覆盖固定值

| 项 | 内容 |
|---|---|
| 典型表现 | 页面显示信道已固定，过一会儿又变；回读与扫描矛盾 |
| 根因 | 「自动信道/抗干扰」仍开启；或隐藏标志仍为 1；设备后台定时优化 |
| 早期发现 | 固定前先关自动优化；回读隐藏标志；隔 10 分钟再扫一次确认没变 |
| 不做会怎样 | 信道规划失效，同频回归；验收数据不可信 |

### F16 在线判据错误

| 项 | 内容 |
|---|---|
| 典型表现 | `ping` 某设备管理 IP 不通，就判它离线并重启，结果全屋断网 |
| 根因 | 部分从机/AP 默认不响应管理 IP；ICMP 被防火墙丢弃 |
| 早期发现 | 在线判据用「BSSID 仍在广播 + 主网关拓扑显示在线 + 客户端能关联」三选二 |
| 不做会怎样 | 误重启关键设备（FTTR 从机/主路由），造成不必要的全屋断网 |

### F17 文档与实机漂移

| 项 | 内容 |
|---|---|
| 典型表现 | 文档写「打印机接 LAN2」，实机在 LAN1；旧结论「不支持 X」仍留在文档里 |
| 根因 | 现场变更后只改一处文档；旧结论没有更正块；多人各自记录 |
| 早期发现 | 开工前做一次「文档事实体检」：端口、地址、型号、能力逐项对照实机；旧结论加更正块 |
| 不做会怎样 | 下一位执行者按错文档操作，拔错线/改错口；复盘引用错事实 |

### F18 端口与授权边界漂移

| 项 | 内容 |
|---|---|
| 典型表现 | 施工中忘了哪根线在哪个口；或顺手改了住户说「不能动」的设备 |
| 根因 | 没有逐口标签；没有把「禁区」写成清单；现场凭记忆 |
| 早期发现 | 每步回报都写「当前各线对应的端口」；开工前把禁区设备/端口列成表并让住户确认 |
| 不做会怎样 | 拔错线导致 IPTV/打印中断；改了运营商设备导致套餐违约或远程锁回 |

## §2 停手信号清单

出现以下任一情况，**立即停手**，不尝试「再改一下看看」：

1. 带外通道不可用，而下一步会切断当前管理通道；
2. 保存后回读值与写入值不一致，连续两次；
3. 出现双默认网关、双网段、169.254 地址；
4. 两端链路只有 10 Mbps，且下一步要测吞吐；
5. 管理页提示「其他用户正在设置」或登录被锁；
6. 设备反复重启，或改动后大面积断网；
7. 页面实际菜单与方案不符，找不到目标字段；
8. 需要试默认口令、恢复出厂、拆机才能继续；
9. 改动会影响 IPTV/电话/宽带账号，而住户未确认；
10. 观察期内反复掉线或粘滞；
11. 关键点位信号低于可用阈值，且无法通过挪位解决；
12. 你不知道当前这根线插在哪个口。

**停手不是失败**，是把「可回滚的小问题」留在可回滚的状态。
**不停会怎样**：小问题叠加成大故障，回滚面从一台设备扩大到全屋，且现场证据被后续操作覆盖。

## §3 已经发生时怎么收场

按顺序，不要跳步：

```text
1. 停手：不再点保存、不再拔线。
2. 留证：截图当前页面、记录时间、记录各线端口、记录当前 IP/路由。
3. 隔离：判断故障边界——是一台设备、一个频段、还是有线/无线整段。
4. 单项回滚：只回退最后改的那一项，不同时改多项。
5. 四态验证：地址获取方式、默认路由、DNS、代理，全部回到预期。
6. 业务验证：网关 ping、外网 ping、关键业务实际动作。
7. 记录：把「改了什么/回滚了什么/还剩什么」写进事故台账。
```

### 回滚优先级

| 现象 | 先回滚什么 | 不要做什么 |
|---|---|---|
| 改 LAN 后管理页打不开 | 回旧 LAN/旧地址；必要时断开上联单机直连 | 不要在现场用双网卡同时接两个网段硬试 |
| 关 DHCP 后拿不到地址 | 临时静态地址进入；恢复 DHCP 后再排查 | 不要直接恢复出厂 |
| 双 DHCP | 先关新增的那个 | 不要靠「重启主路由」碰运气 |
| 双 NAT | 把上联从 WAN 改回 LAN | 不要同时改 SSID |
| 漫游变差 | 回上一版信道/带宽 | 不要靠降功率掩盖 |
| 从机失联 | 用 BSSID/拓扑确认；不要 ping 管理 IP 就重启 | 不要拔从机光纤 |

**必须**一次只回滚一项，并回读。
**不做会怎样**：同时回滚多项，无法知道哪一项生效；下次还会踩同一个坑。

## §4 复盘模板（直接原因 / 共性根因 / 新增规则）

```markdown
## 事件 <ID>：<一句话标题>

- 时间：
- 阶段/设备：
- 动作（预期）：
- 实际结果：
- 发现方式：
- 直接原因：
- 共性根因（对应 F01–F18）：
- 影响范围：
- 处置与回滚：
- 新增/修改规则（编号 + 一句话 + 不做会怎样）：
- 如何在下次更早发现（可执行检查）：
- 验证方式（命令/页面/证据）：
```

### 写复盘的三个要求

1. **直接原因写到可复现**：不是「设备问题」，而是「保存按钮只点了 2.4G 那一个」。
2. **共性根因只选一个主因**：对应 F01–F18，便于统计。
3. **新增规则必须能执行**：写「保存后强刷重进回读」，不写「要细心」。

**不做会怎样**：同类事故换个设备再发生一次；复盘变成追责记录，不产生可复用资产。

## §5 开工前 10 分钟自查

- [ ] 我的关键结论里，哪些是 B/C 级证据？是否已标「待复核」？
- [ ] 这台设备有几个保存按钮？是否分频段？
- [ ] 保存后我打算怎么回读？强刷/重进/重启后回读做哪一项？
- [ ] 本机有没有断链网卡的旧地址/旧路由？插线前后各看一次？
- [ ] 两端链路速率是多少？低于 100 Mbps 时吞吐是否已排除出判据？
- [ ] 验收口径写了吗？判据/观察项/不作判据各有哪些？
- [ ] 关键结论有两源吗？BSSID 是否三路交叉？
- [ ] 临时静态地址/DNS/代理的还原步骤写了吗？还原后回读哪四项？
- [ ] 敏感字段白名单定了吗？密码会不会进日志？
- [ ] 现在有几个管理会话？失败一次会不会锁定？
- [ ] 下一步会不会切断我自己的连接？有没有带外通道？
- [ ] before 快照有吗？after 打算用什么同格式导出？
- [ ] 目标矩阵是否逐台逐频段？有没有漏 5G/隐藏 SSID？
- [ ] 自动信道/优化关了吗？隐藏标志回读了吗？
- [ ] 在线判据是 BSSID/拓扑，还是错误的 ping 管理 IP？
- [ ] 文档里的端口/地址/能力与实机一致吗？
- [ ] 每根线贴标签了吗？禁区设备/端口让住户确认了吗？

**必须**至少勾完前 12 项再开工。
**不做会怎样**：这些正是实际部署事故里最高频的触发点；10 分钟自查能挡掉大部分返工。
