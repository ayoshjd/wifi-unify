# 02 · 决策树

> 用法：拿着 `01` 的 C5 能力矩阵，对每台设备依次走树，把结论写进 §7 决策记录表。
> 原则：**先判「能不能」，再判「要不要」**；不能当 AP 的设备不要硬改。
> 三条硬规则：
> 1. 任何方案都不能切断执行者到主网关的管理通道；
> 2. 能力不足时选择降级，并在验收里写明「未达成」，不允许假装达成；
> 3. 一次只改一台，改完回读通过才走下一条树。

---

## 目录

- 树 1 这台设备能不能当 AP
- 树 2 它的 LAN 地址能不能改

- 树 5 只有无线回程怎么办
- 树 6 主路由不能动怎么办
- §7 决策记录表模板

## 树 1 这台设备能不能当 AP

```text
Q1 有独立「AP 模式 / 无线接入点模式 / 桥接模式」吗？
├─ 有 ────────────────→ 方案 A：直接用 AP 模式
│                        仍需确认：关 DHCP、LAN 可改、上联插 LAN
└─ 无
   Q2 能关闭 DHCP 服务器吗？
   ├─ 不能 ───────────→ 方案 E：只能当路由（独立网段/独立 SSID），不参与漫游
   └─ 能
      Q3 能把 LAN 地址改到主网段、且地址在 DHCP 池外吗？
      ├─ 不能 ────────→ 方案 D：保持独立网段，或换设备/加 AP
      └─ 能
         Q4 有 LAN 口可接上联（不是只有 WAN）吗？
         ├─ 没有 ──────→ 方案 D
         └─ 有
            Q5 能改 SSID / 加密 / PSK 吗？
            ├─ 不能 ───→ 方案 C：可当二层 AP，但 SSID 无法统一（只能作为兼容网）
            └─ 能 ─────→ 方案 B：三件套 AP（关 DHCP + 改 LAN + 上联插 LAN）
```

### 方案对照

| 方案 | 做法 | 达成 G1–G7 | 代价/风险 | 验收注意 |
|---|---|---|---|---|
| A 官方 AP 模式 | 选 AP/桥接模式，关 DHCP，上联插 LAN | 全部可达成 | 某些固件 AP 模式仍保留 DHCP，需复查 | 回读 DHCP 状态 |
| B 三件套 AP | 关 DHCP → 改 LAN → 上联插 LAN → 统一无线 | 全部可达成 | 顺序错会出双 DHCP/双 NAT | 每步回读；改 LAN 后从主网侧验证 |
| C 二层 AP 但 SSID 不可改 | 只做「关 DHCP + 改 LAN + 插 LAN」 | G3–G5 可达成，G1/G2 不达成 | 多一个 SSID，不能自动漫游 | 验收写明「未纳入统一」 |
| D 保持独立网段 | 不接 LAN，或接 WAN 做二级路由 | 基本不达成 | 双 NAT/双 DHCP；只能手动切 | 明确告知住户目标未达成 |
| E 只能当路由 | 保留其 DHCP/NAT，独立 SSID | 不达成 | 网络分裂；排查困难 | 建议换设备或加 AP |

**必须**在 Q1–Q5 都有 A 级证据后才选方案。
**不做会怎样**：凭「一般都有 AP 模式」直接改，遇到没有 AP 模式的设备时，会在关 DHCP 后发现无法改 LAN，设备失联或网络分裂。

### 方案 B 的执行顺序（不能乱）

```text
1. 拔该设备上联/WAN
2. 关 DHCP
3. 改 LAN 到主网段池外
4. 上联插该设备 LAN 口
5. 统一 SSID/加密/PSK（逐频段保存、逐频段回读）
6. 设信道/带宽
7. 回读 + 客户端实测
```

**为什么不能先改 SSID**：先改 SSID 会让客户端立刻尝试连新名，而此时 DHCP 还没关、LAN 还没改，正好落进「同名 SSID + 双 DHCP」的冲突窗口。
**不做会怎样**：住户手机连上新名却拿到错误网关，表现为「连上了但不能上网」，且你很难判断是哪台设备发的地址。

## 树 2 它的 LAN 地址能不能改

```text
Q1 管理页有 LAN/IP 设置入口吗？
├─ 没有 ────────────→ 不能改 → 走树 1 的方案 C/D/E
└─ 有
   Q2 目标地址在主网段内、且不在 DHCP 池里吗？
   ├─ 不在池里 ──────→ 可改（记录新地址与登录路径）
   └─ 在池里
      Q3 能改 DHCP 池，把目标地址让出来吗？
      ├─ 能 ─────────→ 先改池，再改 LAN
      └─ 不能 ───────→ 换一个池外地址；或先给该地址做静态绑定/保留
```

### 改 LAN 前的三个推演

1. **改完从哪里登录？** 记录「网卡 → 地址 → 新管理地址」的完整路径。
2. **旧地址会不会残留？** 本机可能保留旧 ARP/旧路由；改完先清 ARP，再从主网侧验证。
3. **如果新地址不通，怎么回滚？** 记录旧地址、旧掩码、旧 DHCP 状态；准备「断开上联、单机直连、临时静态地址」的回滚路径。

**必须**在改之前写下这三条。
**不做会怎样**：改完新地址不通，旧地址也不通，只能恢复出厂；而恢复出厂会丢宽带/IPTV 配置。

### 地址规划建议

| 用途 | 建议 | 理由 |
|---|---|---|
| 主网关 | 网段第 1 个地址（如 `.1`） | 客户端默认网关，固定 |
| AP 固定地址 | `.2`–`.9` 或池外任意 | 便于记忆，避开池 |
| DHCP 池 | `.100`–`.199`（或按需） | 与固定地址分离 |
| 打印机/NAS | 池外固定，或 DHCP 保留 | 避免地址漂移 |
| 临时施工地址 | 单独记在本机，不写进设备 | 用完必须恢复 DHCP |

**必须**让 AP 固定地址与 DHCP 池不重叠。
**不做会怎样**：池里发出同一地址，出现 ARP 冲突/双网关，表现为随机断网。

## 树 3 必须保留、不能关的设备怎么处理

先分类，再决定：

```text
Q1 它是主出口（拨号/唯一 NAT）吗？
├─ 是 → 不动它；在它下面挂 AP；所有 AP 改到它的网段
│       若它的 DHCP 池无法避开 AP 地址 → 见树 6
└─ 否
   Q2 它是 FTTR 从机 / Mesh 卫星 / 运营商扩展点吗？
   ├─ 是 → 通过主网关的「从网关/子路由」页调射频
   │       不关、不断电、不拔回程；SSID 跟随主机
   └─ 否
      Q3 它承载 IPTV/电话/监控专口吗？
      ├─ 是 → 不动其端口与 VLAN；AP 不要插到专口
      └─ 否
         Q4 它被运营商远程管理（TR-069）吗？
         ├─ 是 → 只改允许项；记录「可能被远程改回」
         └─ 否 → 按树 1 正常处理
```

### 处理原则

| 设备类型 | 能改 | 不能做 | 在线/成功判据 |
|---|---|---|---|
| FTTR 从机 | 信道、带宽、功率（通过主机页） | 关电、拔光纤/回程、恢复出厂 | BSSID 仍在广播 + 主机拓扑显示在线 |
| Mesh 卫星 | 跟随主节点；位置可挪 | 单独改 SSID/加密、改 LAN、刷固件 | 卫星 BSSID 同名同密 |
| IPTV/电话专口 | 不动 | 改 VLAN、把 AP 插到专口 | 机顶盒/电话实际可用 |
| 运营商锁设备 | 页面允许的项 | 恢复出厂、试默认口令、拆机 | 业务可用 + 配置未被远程改回 |

**必须**用「BSSID 广播 + 主网关拓扑」判断从机/卫星是否在线，不用 `ping 管理 IP`。
**不做会怎样**：很多从机的管理 IP 本来就不通，你会误判它离线，然后去重启它，导致全屋断网。

## 树 4 完全不可管理的设备怎么处理

```text
Q1 能物理接近并挪位置吗？
├─ 能 → 挪到覆盖更合理的位置；不改变其配置
└─ 不能
   Q2 能把它从网络里摘掉而不影响关键业务吗？
   ├─ 能 → 摘掉/停用；减少一个 DHCP/NAT 源
   └─ 不能
      Q3 它是否在发 DHCP/NAT？
      ├─ 是 → 不能接进主网 LAN；只能让它保持独立网段/独立 SSID
      └─ 否 → 可当纯交换机/纯无线接入使用（但仍无法统一 SSID）
```

### 能做什么

- 客户端侧取证：扫描 BSSID、测漫游、测质量；
- 把它当作「兼容网」：给一个不同 SSID，明确不参与漫游；
- 建议住户联系运营商/房东，或更换设备；
- 在验收里写明「该设备未纳入统一」。

### 不能做什么

- 试默认口令（可能锁定）；
- 恢复出厂（丢宽带/IPTV/端口绑定）；
- 拆机、刷第三方固件；
- 把它接进主网 LAN 而不确认其 DHCP 状态。

**不做会怎样**：强行重置一台不可管设备，可能让宽带账号丢失、IPTV 失效，恢复成本远高于「少统一一台」。

## 树 5 只有无线回程怎么办

```text
Q1 有任何一个房间能用网线回程吗？
├─ 有 → 优先有线；无线只补盲区（混合拓扑，见 PLAYBOOK §4.5）
└─ 没有
   Q2 上游（主路由）信号在候选位置 ≥ -65 dBm 吗？
   ├─ 是 → 中继/无线 Mesh 放在该位置
   └─ 否 → 换位置；仍不行则接受该区域弱覆盖，不叠加多级中继
```

### 无线回程的硬约束

| 项 | 规则 | 不做会怎样 |
|---|---|---|
| 层级 | 最多 1 级中继 | 多级中继吞吐指数下降，延迟翻倍 |
| 位置 | 上游信号 ≥-65 dBm | 信号放大器变成噪声放大器 |
| 信道 | 能固定就固定到上游信道 | 中继跟着上游跳，客户端反复重连 |
| SSID | 与主一致，加密/PSK 一致 | 不一致则永远手动切 |
| 验收 | 断流阈值放宽到 3–5 s，并注明「无线回程」 | 用有线标准验收无线回程，永远不达标 |

**必须**在验收里标注「无线回程」。
**不做会怎样**：住户以为「和有线一样」，实际中继侧速率减半、延迟更高，体验落差变成投诉。

## 树 6 主路由不能动怎么办

```text
Q1 主路由是唯一 NAT + 唯一 DHCP，且完全不能改吗？
├─ 是 → 接受它的网段；所有 AP 改到该网段；AP 关 DHCP
│       若 DHCP 池覆盖全段 → 见 Q2
└─ 否 → 按 PLAYBOOK P2 正常收口
   Q2 DHCP 池无法缩小/无法保留地址吗？
   ├─ 能保留/绑定 → 给 AP 做 DHCP 保留（按 MAC）
   └─ 不能
      Q3 AP 能否用 DHCP 获取地址并稳定？
      ├─ 能 → AP 用 DHCP，但管理地址可能变化；记录并接受
      └─ 不能 → AP 用池外静态地址，若冲突则逐个试；仍不行则保持独立网段
```

### 主路由不可动时的目标降级

| 可改项 | 结果 |
|---|---|
| 主路由 SSID/密码可改 | 以它为主 SSID，其他 AP 跟随 |
| 主路由信道可改 | 其他 AP 避开；不可改则其他 AP 避开它 |
| 主路由 DHCP 可关 | 由另一台设备做 DHCP（少见，慎用） |
| 主路由完全不可改 | 接受其网段与 SSID；其他 AP 尽量跟随；不能跟随的写「未纳入统一」 |

**必须**记录「主路由可能被运营商远程改回」的风险。
**不做会怎样**：验收通过后一周配置被改回，住户以为方案失效，实际是远程管理覆盖。

## §7 决策记录表模板

每台设备一行，**没有填完不允许开工**：

| 设备/位置 | 能力摘要 | 候选方案 | 选择 | 依据（证据等级） | 风险 | 回滚方式 | 对验收的影响 |
|---|---|---|---|---|---|---|---|
| `<设备A>/近端` | 有 AP 模式；可关 DHCP；LAN 可改；2.4G 1/6/11；5G 36–64；双保存按钮 | A/B | A | 页面回读 A | AP 模式仍可能保留 DHCP | 切回路由模式，恢复原 LAN/DHCP | 无 |
| `<设备B>/居中` | 无 AP 模式；可关 DHCP；LAN 可改；单频 2.4G | B | B | 页面回读 A | 改 LAN 后新地址不通 | 断开上联，单机直连旧地址 | 不参与 5G 判据 |
| `<设备C>/远端` | 不可管理 | 降级 | 独立 SSID | 住户确认 C | 可能发 DHCP | 不接入主网 LAN | 明确「未纳入统一」 |

### 填写规则

1. **能力摘要只写已回读的事实**，不写「应该支持」。
2. **选择必须对应树 1–6 的某个方案编号**，不写「看情况」。
3. **依据写证据等级**：A=回读/命令；B=单源推断；C=经验。C 级不得单独支撑选择。
4. **回滚方式必须可执行**：写清拔哪根线、登哪个地址、改回哪个值。
5. **对验收的影响必须写**：这台设备是否参与 G1–G7，哪些判据要降级或排除。

**必须**在开工前让住户确认这张表（至少确认「不能动的设备」与「会断网的窗口」）。
**不做会怎样**：施工中才发现某台设备不能改，方案要重排，已经改好的设备可能白改。
