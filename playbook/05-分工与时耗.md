# 05 · 分工与时耗

> 目的：让别人在开工前判断「这事要不要做、需要几个人、要被打断多少次」。
> 说明：轮次是经验区间，不是承诺；设备越不可管理、越需要换线，轮次越多。
> 「一轮人机交互」的定义：**一条指令 → 人做一次动作/确认 → 一次回读或验证 → 一次回报**。批量操作不算一轮，因为它无法定位失败点。

## §1 只能人做的动作

| # | 动作 | 为什么必须人做 | 频次 | 跳过会怎样 |
|---|---|---|---|---|
| H1 | 插拔网线、换端口 | 物理动作；需要看标签/听卡扣 | 每台 AP 2–4 次 | 拔错线，IPTV/打印中断；远程无法纠正 |
| H2 | 在设备页面输入密码/PSK | 敏感信息不落盘、不进日志 | 每台 1–2 次 | 密码进入工具输出，无法回收 |
| H3 | 物理走动测漫游 | 需要真实位置与遮挡 | 每轮 3–5 站，2–3 轮 | 用静态测点代替走动，漏掉粘滞/断流 |
| H4 | 看指示灯、摸温度、听异响 | 远程拿不到 | 每台开机/重启后 | 漏掉硬件故障/过热重启，误判为配置问题 |
| H5 | 业务验证（打印、IPTV、监控） | 需要实际操作业务 | 收尾 1 次，问题复测 | 网络通但业务不通，验收失真 |
| H6 | 确认「不能动」的边界与授权 | 只有住户知道约束 | 开工前 1 次 | 改了运营商设备/专口，违约或断业务 |
| H7 | 拍设备标签、记录端口 | 需要现场视角 | 进场 10–15 张 | 型号/地址/端口记录错误，后续全错 |
| H8 | 断开/连接本机 Wi-Fi | 涉及操作者自身通道 | 切换测点 3–5 次 | 自动化脚本误断管理通道，任务中断 |
| H9 | 判断「哪个是主路由/机顶盒/从机」 | 需要看现场连线与住户说明 | 进场 1 次 | 把从机当主路由改，全屋断网 |
| H10 | 设备页面点「保存/应用」 | 多数家用设备无 API；需人确认按钮范围 | 每台 2–6 次 | 脚本无法可靠点页面；漏点保存按钮 |

**必须**由人完成的动作，不要试图用脚本替代。
**不做会怎样**：脚本能跑但无法处理物理/权限/业务语义，出错时无人能判断现场状态。

## §2 可以自动化的动作

| # | 动作 | 工具/脚本 | 输出 | 平台限制 |
|---|---|---|---|---|
| A1 | 本机网络基线快照 | `Get-NetSnapshot.ps1` | ipconfig/route/DNS/WLAN/链路 | Windows |
| A2 | 一致性自检 | `Test-NetConfigConsistency.ps1` | 网关唯一/单 DHCP/无 169.254/SSID | Windows |
| A3 | 链路质量与事件计数 | `Get-LinkQuality.ps1` | 速率/双工/断链事件 | Windows |
| A4 | BSSID 扫描 | `Get-BssidList.ps1` | BSSID/SSID/信道/RSSI | Windows；手机用 App |
| A5 | 漫游断流计算 | `Measure-RoamingGap.ps1` | 每条 gap/8002/汇总 | Windows |
| A6 | 字段变更记录 | `New-FieldChangeRecord.ps1` | before/写入/回读表 | pwsh 7+（纯文件，生成 Markdown） |
| A7 | 回读比对 | `Compare-FieldReadback.ps1` | 差异表/退出码 | pwsh 7+（纯文件） |
| A8 | 多保存按钮清单 | `New-MultiSaveChecklist.ps1` | 逐段保存/回读清单 | pwsh 7+（纯文件） |
| A9 | 敏感信息泄漏扫描 | `Test-SensitiveLeak.ps1` | 命中文件/行号 | pwsh 7+（纯文件） |
| A10 | 文档事实体检 | `Compare-DocFacts.ps1` | 文档与扫描/系统不一致项 | Windows（依赖扫描） |
| A11 | 阶段停点闸门 | `Test-PhaseGate.ps1` | 快照成对/口径/遗留/审批检查 | pwsh 7+（纯文件） |
| A12 | 快照差异 | `Compare-Object`/diff | 计划外差异 | pwsh 7+（纯文件） |

**自动化只做「读」和「比对」；写操作必须由人确认。**
**不做会怎样**：手工抄 7 份快照容易漏项；没有 diff 就无法证明「只改了计划内项」。

## §3 半自动：人读页面 + 脚本留证

| 动作 | 人做什么 | 脚本做什么 | 为什么不能全自动 |
|---|---|---|---|
| 页面字段回读 | 打开页面、读值、口述/粘贴 | 记录、与 before 比对、标差异 | 家用设备无 API；页面结构各异 |
| 密码一致性 | 两次输入/确认 | 只记录「一致/不一致」与长度，不记明文 | 敏感信息不能进脚本参数/日志 |
| 信道确认 | 看当前状态页/扫描 | 扫描、汇总、与规划比对 | 页面可能未持久化，需要双证据 |
| 设备在线 | 看拓扑/指示灯 | 扫描 BSSID、ping 网关 | 管理 IP 可能不响应 |
| 业务验证 | 实际打印/播放/开关 | 记录时间与结果 | 业务语义无法脚本判断 |

**必须**让「人读」与「脚本记」分离：人只负责事实，脚本负责一致性与留证。
**不做会怎样**：人既读又记，容易把「期望值」写成「实际值」；脚本只做比对才能发现偏差。

## §4 交互轮次估算

### 4.1 分阶段

| 阶段 | 典型轮次 | 说明 |
|---|---|---|
| P0 进场侦察 | 2–3 | 一次现场清点 + 一次补测 + 一次确认 |
| P1 通道与基线 | 3–5 | 建通道、导快照、改非目标 SSID、测基线 |
| P2 主出口收口 | 2–4 | 定池、定基准、关自动优化、备份 |
| P3 单台 AP 化 | 6–10 / 台 | 拔线、关 DHCP、改 LAN、插回、改无线、设信道、回读、实测 |
| P4 射频收口 | 4–6 | 扫描、分配、逐台设置、复扫 |
| P5 验收取证 | 6–10 | BSSID 三路、漫游 2 轮、质量、业务、结论 |
| P6 观察与交接 | 2–3 | 观察记录、遗留登记、交接 |

### 4.2 总量估算

| 场景 | 设备数 | 估算轮次 | 说明 |
|---|---|---|---|
| 小户型，2 台可管理 AP，有线回程 | 2 | 30–45 | 最顺的情况 |
| 常见三居，3–4 台，含 1 台不可管理 | 3–4 | 45–70 | 多数家庭 |
| 复杂，4–6 台，含 FTTR/无线回程/无备线 | 4–6 | 70–110 | 每多一个约束加 5–15 轮 |
| 每发生一次事故 | — | +3–6 | 停手、留证、单项回滚、复测 |

**这些是「人机交互轮次」，不是小时数。** 实际耗时取决于住户是否在场、设备页面响应、是否需要等重启、是否要换线。
**必须**按阶段设停点，不要试图一次对话做完。
**不做会怎样**：批量操作失败时无法定位是哪一步；回滚要全部重来。

### 4.3 轮次为什么会膨胀

| 因素 | 增加轮次 | 原因 |
|---|---|---|
| 设备不可管理 | +2–4 / 台 | 只能客户端侧取证，无法回读 |
| 无备用网线 | +3–5 | 每根线都要反复确认，不能拔了换 |
| 现场只有手机 | +5–10 | 无事件日志，扫描/回读都更慢 |
| 必须保持在线 | +3–5 | 不能断网测试，只能低峰/后台 |
| 运营商远程管理 | +2–4 | 改完可能被改回，需要复测 |
| 多保存按钮/分频段 | +1–2 / 台 | 逐段保存逐段回读 |
| 每出现一次「页面与方案不符」 | +3–5 | 停手、查菜单、重写步骤 |

## §5 影响成本的因素

| 因素 | 低成本 | 高成本 |
|---|---|---|
| 设备可管理性 | 全部有网页/可回读 | 多台不可管理/只有 App |
| 回程 | 每个房间有网线 | 只有无线/电力猫 |
| 设备数量 | 2–3 台 | 5 台以上/多层 |
| 约束 | 可短时断网 | 不能断网/有 IPTV/电话 |
| 人员 | 住户在场、有密码 | 住户不在、密码在运营商 |
| 工具 | 笔记本 + 备用线 | 只有手机 |
| 文档 | 有拓扑/密码/账号 | 全靠现场摸 |

## §6 值不值得做：判断清单

### 6.1 值得做（多数满足）

- [ ] 无线设备 ≥3 台，且存在手动切网/信号死角；
- [ ] 至少有一台可管理设备能当 AP；
- [ ] 有或能拉有线回程；
- [ ] 能拿到管理密码，或住户能配合；
- [ ] 能接受 10–30 分钟短时断网；
- [ ] 有人愿意在观察期记录问题。

### 6.2 不建议做（任一命中）

- [ ] 唯一可改的设备一改就切断唯一管理通道，且无第二通道；
- [ ] 关键设备（FTTR 从机/IPTV/电话）完全不能动，而它正是问题源；
- [ ] 住户不接受任何断网，也不接受降级方案；
- [ ] 现场只有手机、无备用线、且设备全部不可管理；
- [ ] 目标是「企业级无缝漫游/高密度」，家用设备无法达成。

### 6.3 更便宜的替代方案

| 问题 | 先试这个 | 成本 |
|---|---|---|
| 一个房间信号弱 | 挪一台 AP/路由的位置 | 0 |
| 有网线但没接 | 有线回程 + AP | 低 |
| 老设备拖后腿 | 换掉一台最老的 | 中 |
| 只有无线回程 | 无线 Mesh/中继（接受减半） | 中 |
| 运营商从机信号差 | 调从机信道/位置，不改主网 | 低 |
| 只想减少手动切网 | 统一 SSID+密码（不追求无缝） | 低 |

**必须**先试 0 成本/低成本项，再决定是否全量改造。
**不做会怎样**：为了「统一」大动干戈，实际只需挪一台设备；投入产出比很差。

## §7 角色分工建议

| 角色 | 职责 | 必须由谁 |
|---|---|---|
| 房主/住户 | 提供密码、确认约束、业务验证、接受断网窗口 | 住户本人 |
| 执行者 | 插拔线、页面操作、现场判断、停手决策 | 在场的人 |
| 记录者 | 快照、回读、证据命名、事故台账 | 可与执行者同一人，但不要同时操作与记录 |
| 复核者 | 按 `03` 复核判据、检查 before/after、读结论 | 未参与施工的人最佳 |

### 最小配置

- 1 人：可完成小户型，但操作与记录会互相打断，轮次增加 20–30%。
- 2 人：一人操作、一人记录/复核，效率最高。
- 3 人以上：只在多楼层/多设备时有必要，否则沟通成本大于收益。

**必须**让「复核者」不看执行者的口头结论，只看证据文件。
**不做会怎样**：执行者自己验收自己，容易把「期望」当「实际」，漏掉反例。

## §8 人机协作协议

1. **一轮一件事**：一条指令只改一个字段/一项配置；改完立即回读。
2. **一轮一回报**：回报写「改了什么、回读是什么、下一步是什么」，不写「已完成」。
3. **停点即暂停**：每阶段结束必须停，等确认后再进入下一阶段；不自动跨阶段。
4. **人不确认，不改**：涉及密码、断网、重启、拔线，必须人明确同意。
5. **异常即停**：页面与方案不符、回读不一致、出现双网关，立即停手报告，不自行发挥。
6. **记录不落密码**：密码只由人输入，脚本只记「是否一致」。

**不做会怎样**：批处理式操作让失败点不可定位；自动跨阶段会把小问题带进下一阶段，回滚面扩大。
