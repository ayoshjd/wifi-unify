# 通用 Wi-Fi 统一打法 · 使用说明

> 这套材料解决一个问题：**换一套房子、换一批设备、换一个运营商之后，如何把多个 Wi-Fi 收敛成一个能自动漫游的网络，并且不把自己锁在门外。**
> 它不是某一次部署的过程记录，而是从过程里抽出来的、与环境无关的做法。示例由一次实际部署泛化而来（已去除型号、地址、时间与房间名），数字仅作量级参考，只作「仅示例」出现。

## 1. 这套材料包含什么

| 文件 | 回答什么问题 | 什么时候读 |
|---|---|---|
| `PLAYBOOK.md` | 目标态是什么、最小充分条件、分几个阶段、每阶段怎么进退 | 第一次做，先读这份 |
| `01-首次进场核查清单.md` | 到陌生环境最初 30–60 分钟怎么摸清现状 | 到现场第一件事 |
| `02-决策树.md` | 设备支持 A 不支持 B 时怎么走 | 核查完、定方案时 |
| `03-验收与取证.md` | 怎么证明真的成了、没工具怎么粗验 | 开工前定口径 + 收尾取证 |
| `04-常见失败模式.md` | 前人踩过哪些坑、怎么早期发现 | 开工前通读，施工中随时查 |
| `05-分工与时耗.md` | 哪些必须人做、大概多少轮交互、值不值得做 | 评估要不要开工时 |

## 2. 三种读法

**第一次做（推荐顺序）**

1. `PLAYBOOK.md` §1–§3：先建立目标态与阶段感；
2. `01`：到现场按表打勾，产出一页现状；
3. `02`：按设备能力做决策，写进决策记录表；
4. `03`：**开工前**把验收口径写死；
5. `04`：通读失败模式，标出本环境最可能中的三条；
6. `05`：确认人手与交互轮次能接受，再开工。

**已经有方案，只想避坑**

`04` → `03` → `PLAYBOOK.md` §8。先看别人怎么翻车，再检查自己的验收口径，最后对照停手信号。

**只想评估要不要做**

`05` → `01` §E。先看成本与前置条件，再看现场能不能满足。

## 3. 与其他材料的关系

- 本目录是公开副本，**不包含**任何原始过程材料（方案、验收、复盘、规则、原始测量）。
- 配套自动化见本仓库根下的 `skill/`。手册讲「为什么与怎么判断」，Skill 讲「用什么命令留证」；两者可独立使用，不必同时采用。
- 手册中的 `[通用]` / `[现场判断]` / `[示例]` 标记是刻意加的：换环境后，只有 `[通用]` 可以直接照用，`[现场判断]` 必须重新测，`[示例]` 不能当步骤。

## 4. 开源前脱敏清单

本目录内的示例已全部使用占位写法（`<SSID>`、`192.0.2.x`、`AA:BB:CC:DD:EE:FF`）。如果你要基于自己的项目改写并公开，逐项确认：

- [ ] 无真实 SSID、BSSID/MAC、管理 IP、宽带账号、PPPoE 口令；
- [ ] 无 Wi-Fi 密码明文或可还原片段（首尾字符、掩码提示都算）；
- [ ] 截图已打码：设备背面标签、无线密码页、宽带账号页、运营商 App；
- [ ] 拓扑图不含真实门牌、户型图、摄像头/打印机主机名；
- [ ] 原始测量文件（ping 日志、扫描日志）已检查是否含 MAC 与内网地址；
- [ ] 复盘里的时间、人名、聊天记录已泛化。

> 判断标准只有一条：**陌生人拿到这份材料，能否定位到你家或连上你的网。** 能，就必须继续脱敏。

## 5. 术语速查

| 术语 | 一句话 |
|---|---|
| SSID / BSSID | 网络名 / 某个具体射频的 MAC，同名 SSID 下可以有多个 BSSID |
| AP 模式 | 只做无线接入、不发地址、不做 NAT 的模式 |
| 二层广播域 | 同一 IP 子网、能直接 ARP 到彼此的范围 |
| 双 NAT | 两层地址转换，常见于「路由接路由 WAN」 |
| 漫游 / 重关联 | 客户端从一个 BSSID 换到另一个，同 SSID 下通常不断 IP |
| 断流 | 漫游过程中完全收不到包的时间 |
| 粘滞 | 明明旁边有更强的 AP，客户端仍挂在远处弱 AP |
| DFS | 5G 中需要避让雷达的信道，可能突然切换 |
| FTTR | 光纤到房间，主网关 + 从网关，从机通常不可独立管理 |

- 修订原则：只增不删；被推翻的结论保留原文并加「更正块」，不静默改写。

> **数值说明**：文中出现的具体量级（如断流 <1 s、0 丢包、时延量级、链路 ≥100 Mbps 门限）来自一次实际部署的实测值，仅作量级参考，不是通用保证；换设备、换户型、换客户端都可能不同。
