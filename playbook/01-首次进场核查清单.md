# 01 · 首次进场核查清单

> 目标：30–60 分钟内回答四个问题——**谁在拨号、有几层 NAT、谁发 DHCP、每台设备能做什么**。
> 原则：这一阶段**只读**。不登录不改、不拔线、不重启、不试默认口令。
> 用法：打印或在手机上逐项打勾；每项写「值 + 来源 + 证据等级（A/B/C）」。
> 时间分配是按「不熟悉现场」估的，熟悉后可压缩；不要为了赶时间跳过 C 段。

---

## B 逻辑拓扑（约 15 分钟）

> 这一段的产出是一张「谁拨号、几层 NAT、谁发 DHCP」的图。**不要靠设备型号推断**，全部用客户端命令验证。

### B1 从客户端看

连上当前主 SSID（或任一能上网的 SSID），执行并记录：

| # | 检查项 | 命令/方法 | 记录 | 证据 |
|---|---|---|---|---|
| B1.1 | 本机地址/掩码/网关 | `ipconfig /all`（Windows）或系统网络详情 | IP ____ / 掩码 ____ / 网关 ____ | A |
| B1.2 | DHCP 服务器 | `ipconfig /all` 的「DHCP 服务器」字段 | ____ | A |
| B1.3 | DNS | 同上 | ____ | A |
| B1.4 | 默认路由条数 | `route print -4` 或 `ip route` | ___ 条；接口：____ | A |
| B1.5 | 到公网的私有跳数 | `tracert -d <公网IP>`（如 223.5.5.5） | 私有地址跳：___ 跳 | A |
| B1.6 | 公网出口 IP | 浏览器访问 IP 查询站，或 `curl ifconfig.me` | ____ | A |
| B1.7 | Wi-Fi 频段/协议/速率 | 系统 Wi-Fi 详情 | 2.4G/5G；协议 ____；速率 ____ | A |
| B1.8 | 当前 BSSID | 系统 Wi-Fi 详情或扫描工具 | ____ | A |
| B1.9 | IPv6 是否有全局地址 | `ipconfig` 看是否有 `2xxx:`/`240e:` 等 | 有 / 无 | A |

**判读规则**

- B1.5 私有跳数 = **NAT 层数** 的近似值。1 跳私有 → 单 NAT；2 跳 → 双 NAT（或 NAT + 路由）。
- B1.6 的公网 IP 与主路由 WAN 口 IP 不同 → 至少一层 NAT；主路由 WAN 口本身是私有地址 → 上游还有一层 NAT。
- B1.2 的 DHCP 服务器就是「谁发地址」。如果它不等于主网关，说明还有第二台 DHCP。

### B2 逐 SSID 交叉

把现场能扫到的 SSID 列出来，逐个连一次（只读，不改），记录：

| SSID | 连上后网关 | DHCP 服务器 | 是否可上网 | 频段 | 备注 |
|---|---|---|---|---|---|
| `<SSID-1>` | | | 是/否 | | |
| `<SSID-2>` | | | 是/否 | | |
| `<SSID-3>` | | | 是/否 | | |

**必须**至少连一次非主 SSID。
**不做会怎样**：不知道哪台设备还在发 DHCP/NAT，改完主网后它继续抢答，出现「有的人能上网、有的人不能」。

### B3 谁在拨号

| 可能形态 | 判断方法 | 记录 |
|---|---|---|
| 光猫路由模式拨号 | 光猫 WAN 状态显示已连接/有公网或运营商地址；下游路由 WAN 拿私有地址 | 是 / 否 |
| 光猫桥接 + 路由拨号 | 光猫 WAN 显示桥接；路由 WAN 有 PPPoE 账号或公网地址 | 是 / 否 |
| 软路由/双路由拨号 | 中间有额外设备；`tracert` 私有跳数 ≥2 | 是 / 否 |
| 不确定 | 看光猫/路由 WAN 页；问住户宽带账号在谁手里 | 待确认 |

**必须**确认到「哪台设备持有宽带账号/拨号」。
**不做会怎样**：误改拨号设备，全屋断网且无法自行恢复（账号可能只有运营商知道）。

| # | 检查项 | 怎么查 | 记录 |
|---|---|---|---|

## D 暗坑排查（约 10 分钟）

逐项确认，命中就打勾并写应对：

- [ ] **同默认 LAN 地址**：两台设备的出厂 LAN 地址相同（如都是 `192.168.<x>.1`）；直接改 AP 会冲突，必须先隔离再改。
- [ ] **运营商远程管理（TR-069）**：光猫可能被远程改回；确认能否关闭，或接受「可能被改回」。
- [ ] **IPTV/电话专口**：改动可能让机顶盒黑屏；确认哪个口、哪个 VLAN。
- [ ] **打印机/摄像头/NAS 静态 IP**：改网段后可能失联；先记录地址与配置方式。
- [ ] **智能家居只支持 2.4G / 只支持 WPA2**：不要为了「更安全」把加密改成设备不支持的模式。
- [ ] **Mesh 回程占口**：主节点 LAN 口可能被卫星占用，别拔。
- [ ] **端口隔离**：开着时同 SSID 终端互不通，会误判为「网络坏了」。
- [ ] **无线定时开关**：夜里自动关 Wi-Fi，会被误判为故障。
- [ ] **接入控制白名单**：改 SSID/密码后新设备可能被拒。
- [ ] **访客网络同名/相似**：扫描时容易误判 BSSID 归属。
- [ ] **双频合一**：关闭可能改善 IoT 配网，也可能破坏漫游，先小范围试。
- [ ] **固件自动升级**：升级可能重置配置；记录版本与开关。
- [ ] **电力猫/交换机环路**：可能出现广播风暴；确认拓扑无环。
- [ ] **隐藏 SSID**：扫描不到不代表不存在；用专业工具看隐藏 BSSID。
- [ ] **DFS 信道**：5G 用到 52–64/100–144 时，可能因雷达避让突然换信道。
- [ ] **设备发热/老化**：老设备在夏天可能随机重启，先记录，不要归因于配置。

**必须**至少确认「同默认 LAN」「IPTV 专口」「智能家居频段/加密」三项。
**不做会怎样**：改到一半才发现机顶盒黑屏或摄像头离线，回滚面扩大，住户信任度下降。

### F2 能力矩阵与决策

- 能力矩阵见 C5；
- 每台设备的处置结论按 `02-决策树.md` 写入决策记录表；
- 至少产出一台「可当 AP」的设备，否则本次目标无法达成，需向住户说明。

### F3 Go / No-Go

**Go（全部满足才开工）**

- [ ] 主网关可管理，或已明确「主路由不可动」的降级分支；
- [ ] 至少一台 AP 可关 DHCP + 改 LAN + 改 SSID/加密；
- [ ] 有可行的带外通道方案（空余 LAN 口 / 第二台设备）；
- [ ] 住户确认断网窗口与授权范围；
- [ ] 关键业务（IPTV/打印/监控）已识别并有回滚预案；
- [ ] 能写出验收口径三分法（判据/观察项/不作判据）。

**No-Go（任一命中，暂停）**

- [ ] 完全拿不到任何管理入口，且住户无法协助；
- [ ] 无法确认谁发 DHCP / 谁拨号；
- [ ] 唯一可改的设备一改就会切断唯一管理通道，且无第二通道；
- [ ] 关键设备不可动，而它是唯一 DHCP/NAT；
- [ ] 住户不接受任何短时断网，也不接受降级方案；
- [ ] 现场无回滚能力（没有密码、没有配置备份、没有备用线且不能停机）。
